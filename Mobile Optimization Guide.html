📱 行動版優化指南

潤讀 So We Read - Direction 4

本文檔為所有 6 個頁面提供詳細的行動版優化規範。

1. 全局設定

1.1 斷點設置

行動版斷點：480px 以下
當屏幕寬度 ≤ 480px 時，應用以下變更：
  • 單欄佈局（移除側欄）
  • 導航轉換為漢堡菜單
  • 字體自適應縮放
  • 圖片有 16px 邊距

1.2 觸控目標最小尺寸

所有可點擊元素最小尺寸：48px × 48px
符合 WCAG 2.5.5 Level AAA 無障礙標準。
  • 按鈕、連結：padding ≥ 12px
  • 菜單項目：height ≥ 48px
  • 表單控制：height ≥ 44px
  • 間距：相鄰元素間距 ≥ 8px

1.3 自適應字體

元素 桌面版 行動版
H1 / Page Title 2.8rem 2rem
H2 / Section 2rem 1.5rem
H3 / Subsection 1.2rem 1.1rem
Body Text 1rem 0.95rem
Meta / Small 0.9rem 0.85rem

2. 導航優化

2.1 漢堡菜單實現

行動版導航規範：
  • Logo：48px × 48px（可點擊，回首頁）
  • 漢堡按鈕：48px × 48px，位於右上角
  • 菜單展開：全寬覆蓋，滑動動畫
  • 菜單項目：48px 高，左對齊，16px padding
  • 背景：白色 (#ffffff)，陰影效果
  • 關閉按鈕：X 圖標，48px × 48px

2.2 菜單結構

|- Logo (首頁)
|- 漢堡按鈕 ☰
   ├─ 首頁
   ├─ 潤讀故事
   ├─ 部落格
   ├─ 聯絡
   ├─ 權利聲明
   └─ 開始閱讀 (CTA 按鈕)

3. 內容區域優化

3.1 邊距與寬度

行動版容器：
  • 左右邊距：16px（不是 40px）
  • 最大寬度：移除（全寬 - 16px 邊距）
  • 頂部邊距：32px（不是 60px）
  • 底部邊距：32px（不是 60px）

3.2 圖片處理

圖片在行動版：
  • 寬度：100% - 32px（16px 左右邊距）
  • 高度：auto（保持寬高比）
  • 最小高度：180px（文章卡片）
  • 邊框半徑：4px
  • 圖片容器邊距：0（圖片自行負責邊距）

4. 各頁面特殊優化

4.1 首頁 (Homepage)

  • Hero 部分：padding 32px 16px
  • 標題字體：2rem（不是 2.8rem）
  • 文章網格：1 欄（不是 3 欄）
  • 訂閱區：padding 32px 16px，按鈕全寬 (max-width: none)
  • 按鈕：全寬 (width: 100%)
  • 表單輸入：stack 垂直排列，全寬

4.2 故事頁 (Story Page)

  • 標題字體：2rem
  • 特色卡片網格：1 欄
  • 卡片 padding：20px（不是 24px）
  • Section spacing：30px（不是 50px）

4.3 部落格頁 (Blog Page)

  • 主欄 + 側欄：→ 單欄 stack
  • 排序按鈕：全寬 stack，48px 高
  • 文章卡片：padding 20px
  • 側欄卡片：移到底部
  • 分類/標籤：移動友善的 flex wrap
  • 分頁：horizontal scroll （可選）或 inline

4.4 文章詳情頁 (Article Page)

  • 主欄 + 側欄：→ 單欄 stack
  • 文章內容 max-width：移除（適應容器寬度）
  • 評論表單：全寬輸入框
  • 側欄（標籤、熱門文章）：移到底部

4.5 聯絡頁 (Contact Page)

  • 表單欄位：全寬 (grid-template-columns: 1fr)
  • 聯絡資訊卡片：1 欄 stack
  • 按鈕：全寬

4.6 權利聲明頁 (Privacy Page)

  • 內容 max-width：移除
  • 標題字體：2rem
  • 列表項目：padding 12px 0

5. 常見元件優化

5.1 表單

  • 輸入框高度：44px（最小）
  • 標籤字體：0.95rem
  • 輸入框字體：1rem（防止自動縮放）
  • 邊距：底部 20px（不是 24px）
  • 按鈕：width 100%，height 48px，font-size 1rem

5.2 卡片

  • Padding：20px（不是 24-32px）
  • 邊框半徑：4px（保持一致）
  • 邊距：底部 16px（不是 32px）
  • box-shadow：0 2px 8px（保持細膩）

5.3 按鈕

  • 最小高度：48px
  • 最小寬度：120px（如果不是全寬）
  • Padding：12px 24px（垂直 12px，水平 24px）
  • 字體：1rem（不小於 0.9rem）
  • 按鈕組間距：8px

6. 實現檢查清單

CSS Media Query

  • 添加 @media (max-width: 480px) 規則到所有頁面
  • 測試於真實手機設備（不只是瀏覽器模擬）
  • 驗證所有觸控目標 ≥ 48px
  • 確保沒有水平溢出

JavaScript（漢堡菜單）

  • 菜單點擊時展開/關閉
  • 點擊菜單項目後自動關閉
  • 點擊背景時關閉菜單
  • ESC 鍵關閉菜單
  • 使用 transform + transition 做動畫（性能更好）

測試

  • iPhone SE / 13 / 14 Plus（375px - 768px）
  • Android 手機（360px - 540px）
  • 平板設備（768px - 1024px）
  • 橫屏 + 豎屏方向
  • 縮放層級 100% - 150%
  • 低速網路下的加載（Chrome DevTools throttling）

無障礙

  • 所有按鈕有 aria-label
  • 菜單有 role="navigation"
  • 觸發按鈕有 aria-expanded
  • 顏色對比度 ≥ 4.5:1（普通文字）
  • 沒有小於 12px 的文字（最小化視覺障礙）

7. 性能優化建議

🚀 性能最佳實踐

  • 圖片優化：使用 WebP 格式（帶 fallback）+ srcset
  • 延遲加載：圖片和下方內容使用 loading="lazy"
  • 關鍵 CSS：內聯首屏 CSS，延遲加載其他樣式
  • 減少重排：避免動態改變 DOM 結構
  • 字體加載：使用 font-display: swap
  • 壓縮：Gzip 壓縮所有資源（≥ 1KB）

9. 部署後監控

⚠️ 上線前檢查

  • 運用 Google Lighthouse 檢查行動版分數（目標 ≥ 90）
  • Core Web Vitals：LCP < 2.5s，FID < 100ms，CLS < 0.1
  • 使用 Chrome DevTools 測試 4G 和 WiFi 下的表現
  • 檢查真實設備上的視覺效果和交互
  • 監控錯誤：使用 Sentry 或類似工具追蹤行動版崩潰

10. 總結

本指南涵蓋了所有關鍵的行動版優化點。開發團隊應遵循以下優先順序：

  1. 必須做：漢堡菜單、48px 觸控目標、單欄佈局、自適應字體
  2. 應該做：圖片優化、表單改善、邊距調整
  3. 可以做：動畫優化、性能調優、無障礙增強
預計開發時間：2-3 天（6 個頁面）
測試時間：1 天（多設備測試）
總計：3-4 天
